# ADR-0002: 收敛机制 = 成本控制

## 状态
已接受

## 背景
对抗式迭代会导致 token 成倍消耗，若无明确的「何时停」，成本会失控，且可能空转死循环。

## 决策
设计三种终止条件，满足任一即停（统一收敛顺序：质量达标 → 无新反馈 → 最大轮数）：

1. **质量达标**：`acceptable=True` 且 `score >= 阈值`（默认 85）→ 成功收敛
2. **无新反馈**：连续 N 轮（默认 2）`issues` 完全相同 → 成功收敛（避免空转烧钱）
3. **达到最大轮数**：硬上限兜底 → 未收敛

关键细节：**未收敛时返回「历史评分最高的版本」而非最后一版**（`get_best_draft`），因为 LLM 迭代不是单调上升的。

## 理由
- 条件 1 是「已够好，停」；条件 2 是「改不动了，别再浪费钱」；条件 3 是「兜底，防成本爆炸」
- 「无新反馈」排在「最大轮数」之前，便于在轮数耗尽前提前收敛、节省成本

## 后果
- 收敛判定抽成纯函数 `convergence.py::evaluate_convergence`，供命令式 `Orchestrator` 与 LangGraph 版共用，避免逻辑漂移
- 配套 token 预算（总预算 + 单轮预算）双重控制，超预算提前终止
