# ADR-0001: 采用 Generator-Critic 对抗式迭代范式

## 状态
已接受

## 背景
单次 LLM 调用产出质量不可控，且缺乏「改哪里、为什么改」的客观依据。人工「AI 输出 → 人肉审查 → 再喂提示词」的循环耗时、不可规模化，是 Agent 落地的核心痛点。

## 决策
用两个角色互相对弈：**Generator** 负责产出，**Critic** 负责结构化挑刺（评分/问题/建议），形成「产出 → 审查 → 按反馈修改 → 再审查」的循环，直到收敛。

## 理由
- 让模型自己扮演「作者」和「评审」两个对立角色，用批判驱动改进（对应 Self-Refine / Reflexion 方法）
- 批判结果结构化（`CritiqueResult`），使「何时停止、是否达标」可判定、可编程
- 相比单次调用，质量提升有迹可循（评分趋势可观测）

## 后果
- 调用次数与 token 成倍增加 → 必须配套收敛机制与成本控制（见 ADR-0002）
- 需要模型分级（Generator 强模型 + Critic 弱模型）以控成本
- 迭代非单调上升 → 未收敛时需返回「历史最优版本」而非最后一版
