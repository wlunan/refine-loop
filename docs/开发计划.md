# Generator-Critic 工程开发计划

> 当前工程主线已收敛为“可验证代码 Agent 工作台”。详细设计、接口方向、阶段拆分和评审问题见 [代码 Agent 深化开发方案](./代码Agent深化开发方案.md)。

## 1. 当前方向

项目优先服务本地 Git 代码仓库：Agent 在隔离工作区修改代码，用户审阅 diff 后确认应用，测试/构建/lint 等确定性验证决定任务是否完成。文本生成、文档和方案能力可以保留为实验入口，但不进入本期主链路。

前端主入口采用单一持久化任务流：**新建任务**仅负责配置需求、工作区和验证项，创建后跳转至任务详情；**任务中心**负责浏览和筛选任务；执行日志、验证证据、暂停与恢复都只在任务详情中呈现。

## 2. 现有基线

- 已有文本/文件模式 Generator-Critic 迭代、工具调用、SSE、长任务和 JSON 检查点。
- 已有独立代码自愈循环、命令验证工具和 4 个 benchmark 任务。
- P0 已完成：文件模式和长任务已使用运行级配置，验证结果会决定代码任务成功、进入检查点和 SSE，并将失败证据回注后续轮次。
- Git worktree、diff 确认、真实路径边界和真正检查点续跑仍未完成。

## 3. 实施顺序

1. **P1：受控变更** — Git worktree、diff 审阅、批准/丢弃、命令 profile、真实路径边界。
2. **P2：可恢复与可观测** — 运行快照、状态机、证据时间线、安全检查点恢复。
3. **P3：评测与交付** — 版本化 benchmark、对照实验、固定 Demo 和 CI。
4. **P3：可复现交付** — benchmark 原始结果、固定 Demo、CI、README 和简历材料。

## 4. 质量门禁

```powershell
# 后端
& 'D:\software\ProgramTool\Miniconda3\envs\agentchat\python.exe' -m pytest tests -q

# 前端
Set-Location frontend
npm run build
```

新增代码 Agent 行为时，必须补充 Mock LLM、验证失败回注、路径边界、变更确认与恢复相关测试；任何效果指标必须能追溯到版本化 benchmark 原始结果。

## 5. P1 已实现验收项

- 代码任务仅在 Git worktree 中规划和执行；原工作区在“应用变更”前不会被 Agent 写入。
- 任务完成后保存文件清单与 binary diff，状态进入 `awaiting_approval`；用户可在任务详情中应用或丢弃变更。
- 内置验证 profile 以参数数组执行，模型侧仅能调用 pytest、lint、Python 脚本三类受控工具；不再暴露任意 shell 命令。
- 文件操作与验证路径都会解析真实路径，拒绝 `..` 和符号链接跳出工作区。

P2 已补齐暂停、取消与进程重启后的任务恢复：已完成的子任务和隔离 worktree 会被保留，当前子任务会回退到可续跑状态。任务事件以 JSONL 追加保存，任务详情可在重进页面后展示持久化证据时间线。版本化 benchmark 继续在 P3 完成。

P3 已建立 benchmark 运行产物契约：每次运行会创建独立目录，写入 `report.md` 与包含任务级原始输出、耗时、运行环境和修复轮次的 `results.json`；尚未执行真实模型实验，因此项目不声明效果指标。

持续集成位于 `.github/workflows/ci.yml`，在 push 和 pull request 时分别运行后端测试与前端生产构建。

## 6. 验证计划自动识别

新建代码任务默认使用 `auto`，后端仅读取工作区元数据并推断一个受控验证 profile：`package.json` 的 `build` 脚本对应 Node build；Python 项目同时发现测试入口时使用 pytest，否则使用 lint；无法识别时明确返回 `none`。页面会在创建前展示推断依据、命令与依赖前提，手动 profile 仅保留在高级设置中作为覆盖项。

自动识别不会安装依赖或执行自定义脚本。Windows 上 Node build 使用 `npm.cmd` 配合 `shell=False` 执行；若命令本身不可用，验证会记录结构化失败证据，而不是让任务线程以 `WinError 2` 异常退出。

## 7. Token 用量账本

Token 用量以每轮为最小持久化单元：每轮 Generator 与 Critic 调用结束后，检查点写入该轮增量 `tokens_used`，任务级 `total_tokens` 同步累加，并通过进度事件推送给页面。任务中断、验证失败或服务重启后，已完成轮次的用量仍可从任务记录和检查点恢复。用量读取兼容 `usage_metadata` 与 OpenAI 兼容接口常见的 `response_metadata.token_usage`。
